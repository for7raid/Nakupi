## Сущности

### 1. Пользователь
- **Идентификатор**: уникальный идентификатор пользователя.
- **Имя**: имя пользователя.
- **Дата регистрации**: дата, когда пользователь зарегистрировался.
- **Дата последнего действия**: дата последнего взаимодействия пользователя с ботом.
- **Список покупок**: коллекция элементов списка покупок.

### 2. Категория
- **Идентификатор**: уникальный идентификатор категории.
- **Название**: название категории (например, "Фрукты", "Овощи").
- **Идентификатор пользователя**: ссылка на пользователя, которому принадлежит категория.

### 3. Элемент списка покупок
- **Идентификатор**: уникальный идентификатор элемента.
- **Название**: название продукта (например, "Яблоки").
- **Количество**: количество продукта.
- **Статус**: статус (куплен/не куплен).
- **Идентификатор категории**: ссылка на категорию, к которой принадлежит элемент.
- **Идентификатор пользователя**: ссылка на пользователя, которому принадлежит элемент.

## События и их взаимодействия

### 1. Пользователь зарегистрировался
- **Взаимодействие**: Бот принимает команду `/start` от пользователя и вызывает метод `addUser` в сервисе, чтобы сохранить информацию о пользователе.

### 2. Категория добавлена
- **Взаимодействие**: Бот обрабатывает команду добавления категории и вызывает метод `addCategory` в сервисе, который, в свою очередь, вызывает метод `addCategory` в репозитории для сохранения категории в базе данных.

### 3. Категория удалена
- **Взаимодействие**: Бот обрабатывает команду удаления категории и вызывает метод `removeCategory` в сервисе, который удаляет категорию и все связанные с ней элементы из базы данных.

### 4. Элемент добавлен
- **Взаимодействие**: Бот обрабатывает команду добавления элемента и вызывает метод `addItem` в сервисе, который сохраняет элемент в базе данных.

### 5. Элемент удален
- **Взаимодействие**: Бот обрабатывает команду удаления элемента и вызывает метод `removeItem` в сервисе, который удаляет элемент из базы данных.

### 6. Элемент помечен как купленный
- **Взаимодействие**: Бот обрабатывает команду пометки элемента как купленного и вызывает метод `updateItemStatus` в сервисе, который обновляет статус элемента в базе данных.

### 7. Список покупок показан
- **Взаимодействие**: Бот обрабатывает команду показа списка и вызывает метод `getItems` в сервисе, который возвращает список элементов для текущего пользователя.

### 8. Элемент обновлен
- **Взаимодействие**: Бот обрабатывает команду обновления элемента и вызывает метод `updateItem` в сервисе, который обновляет элемент в базе данных.

### 9. Напоминание о покупке отправлено
- **Взаимодействие**: Бот отправляет уведомление пользователю о предстоящих покупках на основе запланированного времени или местоположения, используя методы уведомлений.

## Взаимодействия

- Пользователь взаимодействует с ботом через команды (например, добавление категории, добавление элемента).
- Бот обрабатывает команды и генерирует соответствующие события.
- Система обновляет состояние сущностей (категории, элементы списка) на основе событий.
- Бот может отправлять уведомления пользователю с напоминаниями о покупках по заданному времени.

## Киллер-фича

### Интеллектуальные напоминания

Система интеллектуальных напоминаний, которая будет использовать ИИ для анализа поведения пользователя и предоставления персонализированных рекомендаций и напоминаний:

- **Анализ привычек покупок**:
  - Бот будет отслеживать, как часто и когда пользователь покупает определенные товары.
  - На основе этих данных бот сможет предлагать напоминания о покупке товаров, которые пользователь часто приобретает в определенное время года или месяца.

- **Геолокационные уведомления**:
  - Если пользователь посещает определенный магазин, бот может отправить уведомление с предложением купить товары из списка, которые находятся в этом магазине.
